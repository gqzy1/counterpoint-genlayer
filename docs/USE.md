# Use the atelier

## Start without a wallet

Open the Playground. In the gallery example, turn off the closure objection. B1 now defeats A1. Turn that objection back on: A2 defeats B1, allowing A1 to stand in the next reasoning round. Select each argument to read its exact wording and explanation.

The second example leaves the two exclusive entrance rules undecided because they attack each other and neither has an undefeated defender. The third example treats courtyard music as related to a quiet room but not a rebuttal. These are authored teaching examples, not live model results.

Select **On GenLayer → Read published discussion** for a real finalized chain record. Open an argument to inspect its signed author, text and status. Scroll through the challenge findings, source quotations and locally reproduced derivation. Export the record if needed.

## Start a public discussion

1. Connect your browser wallet on Stable Studionet. OKX is selected when available. Free temporary participants are optional for zero-value Studio testing; each new participant has a separate address in this tab.
2. Use the configured verified contract. A custom address must have identical deployed source and protocol. **Deploy bundled source** creates a separate instance; review it before signing.
3. Open the **Open a discussion** tab. Supply a new lowercase ID, a precise question, and 2–4 distinct nonzero wallet addresses, with your current wallet first. The addresses receive seats A, B, C, D in that order.
4. Review and submit. Wait until the transaction journal reports finalized success and the created record is read back. Copy the discussion reference and share it with the invited participants.
5. Each participant opens that reference with the same contract, selects their own signing wallet, and opens **Sign your voice**. Supply two titled arguments. Add up to four challenges, each starting at one of that participant's own argument slots. A target can reference another invited participant's reserved slot before they submit.
6. Describe the actual argument in its text. A challenge's explanatory basis cannot replace missing reasoning in the source argument. Statements are immutable once signed.
7. After all participants submit, **Map with GenLayer** becomes available. Any wallet can request this computation against the fixed signed-input digest.
8. A MAPPED result contains the grounded labelling. REVIEW means at least one relation was ambiguous, so no complete labelling is published. A correction requires a fresh discussion.

## Pending transactions

Do not send a duplicate because finality is taking time. **Recheck saved transaction** tracks the same hash. A refresh preserves the public pending intent, but discards temporary signing keys. A pending transaction can still be checked without those keys.

**Export journal** contains public transaction intents, hashes, observed receipts and successful readbacks from this tab. **Export record** contains the discussion and read timestamp. Neither file contains signing keys.
